# PRD — JARVIS: منصة المساعد الذكي الصوتي

Nov 3, 2026 · @ibrahim

## الملخص والرؤية

JARVIS مساعد ذكي بتكلمه بالصوت بالعامية المصرية، وهو بيجمعلك شغل الوكالة والكورسات والسوشيال في مكان واحد. بيجاوب لايف بصوت Gemini، وبيقرا الداتا من n8n و Perfex و Evolution API، وبيبعتلك تقارير يومية من غير ما تسأل.

**المشكلة:** الداتا متفرقة على Perfex و 3 أرقام واتساب و 4 منصات سوشيال وفريق كامل. معرفة "إيه اللي حصل النهارده" بتاخد من إبراهيم وقت كل يوم بيقضيه يفتح أدوات ويسأل ناس.

**الحل:** واجهة واحدة بالصوت ولوحة تحكم (Next.js)، والداتا كلها متخزنة في Supabase. السؤال بيبقى جملة واحدة، والإجابة صوت وأرقام حقيقية.

**اللي اتأكد منه في اختبار 3 نوفمبر:** Gemini Live فهم العامية المصرية والكلمات الإنجليزي اللي جواها، ونادى tool الليدز لوحده، ورد بصوت مصري مقنع. الاختبار كشف كمان 3 مشاكل لازم تتحل قبل الإنتاج: الصدى، والدوشة اللي بتتفهم كلام، والـ agent اللي ادّعى إنه بعت واتساب وهو مبعتش.

## الأهداف ومؤشرات النجاح

الهدف الأساسي إن إبراهيم يعرف حالة الشغل كله في دقيقة واحدة بالصوت، من غير ما يفتح أي أداة.

| الهدف | المؤشر | المستهدف |
|---|---|---|
| تقرير يومي من غير مجهود | التقرير الصباحي وصل في ميعاده | 7 أيام من 7 |
| ردود سريعة في اللايف | الوقت من نهاية السؤال لأول صوت | أقل من 2 ثانية (من غير tool)، وأقل من 5 ثواني (مع tool) |
| دقة الفهم | أوامر اتفهمت صح من أول مرة | 90% أو أكتر |
| الأمانة | مرات إنه ادّعى إنه عمل حاجة هو معملهاش | صفر |
| مبيعات الكورسات | نسبة المحادثات اللي اتقفلت بيع من واتساب الكورسات | تتحدد بعد أسبوعين قياس (baseline) |

**برّه النطاق في النسخة دي:** موديلات محلية على السيرفر، والتحكم في البيت الذكي، وأي فعل مالي أو حذف من غير موافقة، وبيع المنصة لعملاء خارجيين.

## المستخدمين والأدوار

المستخدم الأساسي واحد هو إبراهيم. الفريق بيظهر في النظام كـ"داتا بتتتبع"، مش كمستخدمين. وعملاء واتساب الكورسات بيتكلموا مع agent منفصل ومحدود الصلاحيات.

| الدور | مين | بيعمل إيه | الصلاحيات |
|---|---|---|---|
| المالك | إبراهيم | بيكلم JARVIS بالصوت، ويستلم التقارير، ويوافق على أي فعل حساس | كل حاجة |
| فريق الميديا | أندرو مينا، أنجي، مادونا | شغلهم اليومي بيتجمع في تقرير | مالهمش دخول على JARVIS في الـ MVP |
| فريق السيلز | تحديد الأسامي سؤال مفتوح | نشاطهم على واتساب السيلز و Perfex بيتجمع في تقرير | مالهمش دخول في الـ MVP |
| عملاء الدعم الفني | عملاء الوكالة على واتساب الدعم | رسايلهم بتتقرا وتتصنف (عنده مشكلة ولا لأ) | JARVIS بيقرا بس، ومبيردش عليهم |
| عملاء الكورسات | أي حد بيبعت لواتساب الكورسات | بيكلموا Sales Agent بيرد ويبيع | الـ agent ده مالوش أي دخول على الـ CRM ولا داتا الوكالة |

## المعمارية والـ Stack

كل الـ agents بيوصلوا للأدوات من باب واحد بس هو n8n، وكل حاجة بتتسجل في Supabase. كده لو غيّرت العقل بعدين (مثلًا تشيل OpenClaw)، الأدوات والداتا مش هتتأثر.

الـ Sales Agent بتاع الكورسات بيكلم عملاء غرباء، علشان كده معزول وبيشوف أدوات الكورسات بس.

| الطبقة | الأداة | دورها |
|---|---|---|
| الصوت اللايف | Gemini 3.1 Flash Live | بيسمع ويرد بالصوت في نفس اللحظة، وبينادي الأدوات (اتجرّب واشتغل) |
| الفويس نوتس والجدولة | OpenClaw + Gemini 3.8 Flash + Gemini TTS | تليجرام وواتساب، والتقرير الصباحي |
| المكالمات (اختياري) | ElevenLabs Agents | مكالمة لايف مربوطة بـ Perfex. الدور بالظبط سؤال مفتوح |
| الأدوات | n8n (MCP Server Trigger) | الباب الوحيد لـ Perfex وEvolution والسوشيال |
| واتساب | Evolution API | 3 أرقام: دعم، وسيلز، وكورسات |
| الداتا | Supabase Cloud | Postgres + pgvector + Realtime + pg_cron |
| الواجهة | Next.js + shadcn/ui (RTL) | شاشة "النهارده" والمايك والموافقات |
| الاستضافة | Coolify (سيرفر البيت) + Hetzner + Cloudflare Tunnel | الـ agents في البيت، والمراقبة من Hetzner |

## نموذج البيانات في Supabase

أي حاجة JARVIS بيقولها لازم يبقى ليها سطر في Supabase. n8n و OpenClaw بيكتبوا في الجداول دي، والـ dashboard والتقارير بيقروا منها. استخدم Supabase Cloud مش self-hosted، لأن سيرفر البيت (8GB وHDD) مش هيشيله.

| الجدول | بيخزن إيه | مين بيكتب فيه |
|---|---|---|
| team_members | أسامي الفريق، والقسم (ميديا/سيلز)، وربطهم بـ Perfex staff id ورقم الواتساب | يدوي |
| wa_instances | أرقام الواتساب التلاتة (support / sales / courses) والـ instance في Evolution | يدوي |
| wa_messages | كل رسالة داخلة وخارجة: الرقم، والنص، والـ instance، والموظف اللي رد | Evolution webhook → n8n |
| wa_conversations | ملخص يومي لكل محادثة: التصنيف (مشكلة/استفسار/بيع)، والحالة (اتحلت ولا لأ)، والمشاعر | n8n + Gemini |
| leads_daily | نسخة يومية من ليدز Perfex | n8n (كل ساعة) |
| team_activity | مين عمل إيه: مهام اتقفلت، وساعات، ومحادثات، وبوستات | n8n |
| social_metrics | مؤشرات يومية لكل منصة: المشاهدات، والمتابعين، والتفاعل | n8n (يومي) |
| briefings | التقارير الصباحية: النص ورابط الصوت | n8n / OpenClaw |
| events | التنبيهات: النوع، والخطورة، واتبعتت امتى | n8n |
| tool_calls | كل أداة اتنادت: الـ agent، والمدخلات، والنتيجة، والوقت | Gemini Live / OpenClaw |
| approvals | الأفعال اللي مستنية تأكيدك، وقرارك، وانتهاء الصلاحية | Agents + الـ dashboard |
| memories | ذاكرة طويلة المدى بـ pgvector: حقائق، تفضيلات، ناس، مشاريع | Agents (v2) |
| course_kb | بيانات الكورسات للـ Sales Agent: الأسعار، والمحتوى، والعروض، والأسئلة الشائعة (pgvector) | يدوي |

**قواعد:** RLS مفعّل على كل الجداول. الـ service role key مابيخرجش برّه السيرفر. التقارير المجدولة بتشتغل بـ pg_cron أو Schedule في n8n.

## الأمان والصلاحيات والموافقات

**القاعدة:** JARVIS بيقرا لوحده، لكن أي حاجة بتخرج لبرّه أو بتغيّر داتا لازم تأكيدك الأول. النظام فيه داتا خاصة (رسايل عملاء وCRM)، وبيستقبل نصوص من غرباء، وقادر يبعت واتساب. التلاتة دول مع بعض هما بالظبط اللي بيخلّي الـ prompt injection خطير.

| المستوى | أمثلة | السياسة |
|---|---|---|
| 0 — قراية | الليدز، التقارير، المؤشرات، ملخص الرسايل | تلقائي ويتسجّل |
| 1 — كتابة داخلية | مهمة في Perfex، ملاحظة، تذكير | تلقائي ويتسجّل، وتقدر تلغيه |
| 2 — خارج لبرّه | رسالة واتساب أو إيميل لعميل | تأكيد إجباري (زرار أو كلمة "أكّد")، وبينتهي بعد 10 دقايق |
| 3 — مدمّر أو فلوس | حذف، تغيير ميزانية إعلان، فاتورة | ممنوع في الـ MVP |

- OpenClaw في container معزول: من غير Docker socket، ومن غير shell tool، ومن غير skills من ClawHub إلا بعد مراجعة. فيه تقارير عن skills خبيثة اترفعت هناك.
- فصل الـ tokens: توكن لأدوات القراية في n8n، وتوكن تاني لأدوات الكتابة، والتاني ده بيعدّي من ورا الموافقة بس.
- الـ Quarantine: أي رسالة واتساب أو إيميل بتتلخّص بـ LLM call مالوش أدوات، والـ agent الأساسي بياخد الملخص كداتا مش كأوامر.
- الـ Sales Agent بتاع الكورسات منفصل تمامًا: بيشوف course_kb بس، وممنوع يدّي خصم أو سعر مش مكتوب فيها، وبيحوّل لبني آدم لو فيه شكوى أو طلب استرداد.
- الأمانة: الـ system prompt بيحدد بالظبط إيه الأدوات المتاحة، وأي رد فيه "عملت" من غير tool call متسجّل بيتعتبر bug.
- المفاتيح: في Coolify env أو Supabase Vault بس، وماتتكتبش في أي شات أو كود. مفتاح Gemini اللي اتكتب في الشات لازم يتغيّر قبل أي بناء.

## المتطلبات غير الوظيفية

| المجال | المطلوب |
|---|---|
| السرعة | اللايف بيرد في أقل من 2 ثانية، والفويس نوت في أقل من 15 ثانية. الاختبار الحالي بياخد حوالي 24 ثانية، فلازم ندمج التفريغ والتفكير في خطوة واحدة |
| الاعتمادية | التقرير الصباحي بيوصل حتى لو سيرفر البيت واقع، لأن مراقبة السيرفر شغالة من Hetzner |
| الاستضافة | سيرفر البيت (8GB): OpenClaw والـ agent service. وعلى Hetzner: n8n وEvolution API، لو هما شغالين هناك فعلًا (محتاج تأكيد). وSupabase Cloud. وVercel أو Coolify للـ dashboard |
| الـ RAM | كل container ليه mem_limit، وهامش 1.5GB فاضي على الأقل في سيرفر البيت |
| التكلفة | هدف شهري أقل من 50 دولار: Gemini (الكريدت اللي معاك)، وSupabase Pro (25 دولار). ولكل API key حد شهري للصرف |
| اللغة | العامية المصرية، والكلمات التقنية بالإنجليزي، والواجهة بالعربي RTL |
| المراقبة | أي أداة اتنادت بتتسجل في tool_calls، وفيه تقرير شهري بالتكلفة والأخطاء |

## خطة الإطلاق

الـ MVP بيغطي القراية والتقارير بس، وخلال أسبوعين. كل مرحلة مابتبدأش غير لما اللي قبلها تعدّي البوابة بتاعتها.

الـ Sales Agent بتاع الكورسات بيتكلم مع عملاء حقيقيين وبيبيعلهم، علشان كده هو آخر حاجة هتشتغل لوحدها من غير مراجعة.
